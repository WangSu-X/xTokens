整体参考PEP8，有以下几个地方需要特别注意：
1. 反对过度抽象：不是所有逻辑都需要 Helper、基类和设计模式，少一层抽象就少一层认知负担。
2. 反对防御性编程滥用：不要用 getattr、hasattr 和无意义的 try/except 掩盖真正的 Bug。
3. 命名和类型应直接表达数据的来源和用途。消息队列的返回类型和接收变量应体现业务语义，例如 `CoreRequestOutput` 和 `request_output`，避免笼统的 `Event` 或 `event`。
4. 拒绝无效测试：测试的价值在于防止真实回归，而不是刷覆盖率。
5. 控制 AI 生成的复杂度：避免 AI 为了一个简单需求生成一堆接口、封装和样板代码。
6. 所有类在 `__init__` 中定义的实例属性统一使用 `self.name` 形式，属性名不加前导下划线。
7. 函数如果是真的内部使用可以写 def _xxx
